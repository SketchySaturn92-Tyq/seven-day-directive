# 《七日指令》内容生产规范（子任务必读）

本文件是内容扩充子任务的共同规范。**先读完本文件，再动手写。**

---

## 一、世界设定（不得改动）

玩家是巨型企业「穹顶集团」的中层。城市被巨大穹顶罩住，穹顶外是酸性雨与黑云。

董事会把处理公司事务做成了牌局：一副十二张「指令卡」，每张写明要拿下哪个目标。
玩家被点名替董事会玩：**每七天必须折掉至少一张，折不出来就换人**（=被处理掉，叫「回收」）。

**牌不是发全的**：开局只有三张，其余靠主线推进、人物关系、委托交差、城区动作、事件逐张挣来。

四条名望轨道：`loyalty` 忠诚（归零＝被清算）、`renown` 声望、`sin` 罪痕（满值＝被回收）、`power` 权柄。

四条指令路径：`control` 操控（笼络人）、`capital` 资本（花钱吞并）、`expand` 扩张（武力占地）、`purge` 清洗（杀人灭口）。

十城区（id 严格照用）：
`tower` 高塔商业区、`exchange` 交易所广场、`lab` 研究所园区、`slum` 下层居住区、`docks` 工业港区、
`orbit` 轨道港、`ring` 环带维修层、`memory` 记忆银行、`salvage` 回收场、`outside` 穹顶之外。

## 四、效果字段允许的键

`run` / `onSolve` / `onExpire` / `onRefuse` 内可用的键：

- `money` 信用点：整数，±15~90
- `intel` 情报：整数，1~5
- `chips` 筹码：整数，1~4
- `gear` 装备：整数，0~2
- `vitality` 体力：整数，±1~2
- `statRandom` 随机属性
- `track` 名望，**只能含** `loyalty` / `renown` / `sin` / `power`，每项 ±1~3
- `grantCard` 直接给牌：`{ n: 1, path: 'purge', tier: 2 }`（`path`、`tier` 可省略）

## 五、写作要求（这是重点，不是装饰）

1. **每条都要有具体物象**：编号、日期、表格、走廊、货梯、冷库、监控截图、湿透的雨衣、结冰的管道、一张手写单。
2. **要是「事情发生了」，不是「你要不要拿好处」**。有具体的施压方、具体的时限、具体的代价。
3. **选项要有真实取舍**：不能三个都是好处。至少一个选项是明确拒绝或承担代价。
4. **矛盾与灰度**：同一件事两个选项各有各的代价，没有标准答案。
5. **文风**：冷静、克制、有细节。像真实公司里发生的事。不热血，不喊口号，不解释道理，不写总结句。
6. **超自然要克制**：涉及「潮」「术士」「记忆银行」时，靠认知错位和话术表现（她知道还没发生的事、用词不像这行业的人、用第三人称描述自己）。**不得出现法术、能量、魔法描述。**
7. **中文引号统一用「」**，不得出现英文引号、弯引号、直角引号。

## 六、写入方式（必须遵守，否则任务失败）

**严禁一次 write_file 写入超过 12KB 的内容。** 上一轮三个子任务全部因为单次写入过大而被截断失败。

正确做法：

1. 用 `write_file` 写入文件头 + 前 25% 内容（≤12KB）。
2. 用 `edit_file` 逐批追加，**每批 ≤12KB**，每批 3~5 条。
3. 追加时用上一批结尾的唯一字符串做 `old_string` 锚点。

文件骨架长这样：

```js
/* 文件说明 */
(function () {
  'use strict';
  window.XXX = [
    // 第 1 批
    { ... },
    // 第 2 批（用 edit_file 追加在第 1 批最后一条后面）
    { ... },
  ];
})();
```

追加时 `old_string` 取上一条的结尾，`new_string` 为「上一条结尾 + 新条目」。
